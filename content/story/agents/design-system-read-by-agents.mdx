<Glance>
In March 2026 my team was told it was turning entirely to agentic development. The first thing I did was make the design system readable by the agents: component docs over MCP, then a generated manifest of every component, token, class name and prop and how they connect, with a one-click setup so a designer could install it next to Figma's.
</Glance>

A design system is a vocabulary. For six years ours lived in a React library, a Storybook, a Figma file and the heads of the people who built it. Developers learned it by reading the source and asking in the team channel. That worked, slowly, for people. It doesn't work at all for a coding agent, which will invent a component that looks right and doesn't exist.

I know, because it did. The first time I had an agent build a sample app with our library, I spent a morning typing variations of one sentence, which boiled down to: use our components, and don't make things up. (One version had more italics than I'm proud of.) By lunch the corrections were a skill file, and the afternoon went better than the morning. Teach it once, write the lesson down, and the next agent starts where the last one left off.

The docs came first. One of the engineers on the team had scaffolded a small MCP server over the winter, at my former lead's direction, that served our component documentation to whatever agent called it. It wasn't a project yet. It was a scaffold with a README. In March I moved those docs into the library proper, gave them a section in Storybook called AI Integration, and it was announced at the monthly release meeting.

Then the manifest, in a day. Docs are what we wrote down. The manifest is what's true. In May I had an agent read every installed package and generate one file describing the system as built: every component, every token, where each token is used, every class name, every prop and which class it toggles. We served that as an MCP of its own, with tools to list, search and trace a token to the components that use it. It was out of date the day it was finished, so it regenerates.

The last mile was a double-click. A small installer that finds your editor's config, backs it up, adds our server and Figma's, and prints a playbook in plain words. Designers were the point: the people most likely to want an agent that speaks the system, and least likely to edit a JSON file to get one.

<Inhabit>
What changed once the agent could read the system: it stopped inventing. It used our tokens instead of writing CSS. It could answer which components use a given token in a second, which is a question I used to answer with grep and a cup of coffee. And it made a second order of tools possible, which the rest of this section is about: a support bot that answers designers from the same docs, a token platform that previews a change across every component, and a styles-only build for the teams that use our look but not our React.

The hard part of an AI transformation isn't the model. It's making your own house legible. Everything we'd left implicit, in chat threads and in people, had to become a file an agent could read. That's not new work. It's the documentation debt we'd been carrying for six years, suddenly with a reason to pay it.

How many teams build with the manifest, and what it saved them, I don't know yet. The design system is public at [magnetic.cisco.com](https://magnetic.cisco.com/). The numbers aren't.
</Inhabit>
